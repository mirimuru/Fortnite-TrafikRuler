# Fortnite-TrafikRuler

Windows 11向けのネットワーク通信監視・振り分けツールです。

## 目的

Fortniteのマッチ開始直後などに発生する大容量通信をWi-Fiへ、少量・低速のゲーム通信をiPhone USBテザリング側のEthernetへ振り分け、モバイルデータ使用量を抑えることを目指します。

> **重要:** 現段階では設計・監視機能から段階的に実装します。通信フローの途中で経路を変更するとTCP/UDPセッションが切断・不安定化する可能性があるため、原則としてフローごとに初回判定した経路を維持します。WFP等による透過的なフロー単位の経路制御は、単なるルートメトリック変更では実現できません。

## 初期仕様

- OS: Windows 11
- 言語: C#
- UI: WPF
- Target Framework: .NET 8
- 対象: TCP / UDP（段階的に対応）
- 判定: 通信フローごとの一定時間あたりの送受信速度
- 既定の振り分け:
  - 高速・大容量フロー: Wi-Fi
  - 低速・少量フロー: iPhoneテザリング（Ethernet）
- 選択したアダプターが利用不能なら、利用可能なもう一方へフォールバック
- 閾値・測定窓・対象プロセスは設定で変更可能にする
- 初期段階は監視専用。実際の経路変更は明示的な有効化後に行う

## 現在の実装状況

### Phase 1A - アダプター単位の通信量監視（実装済み・未実機検証）

- .NET 8 WPFアプリの初期構成
- ネットワークアダプターの一覧・種類・接続状態を表示
- アダプターごとの受信/送信速度を1秒間隔で算出
- リンク速度と送受信合計速度を表示
- GitHub ActionsでWindows上のビルドを実行

**現在の制限:** まだアダプター全体の通信量だけを表示します。FortniteのPID別・TCP/UDPフロー別の通信量は取得しておらず、通信経路の変更も行いません。

### ビルド・起動

Windowsで.NET 8 SDKをインストールし、リポジトリのルートで実行します。

```powershell
dotnet build .\FortniteTrafficRuler.sln -c Release
dotnet run --project .\src\FortniteTrafficRuler\FortniteTrafficRuler.csproj
```

## 重要な設計上の注意

1. **速度判定には観測期間が必要**  
   新規フローの開始直後は速度が分からないため、最初の数秒を観測期間とします。観測中のパケットを安全に保留・再注入できる仕組みがない段階では、監視結果を記録するだけにします。
2. **同じフロー内の通信を分割しない**  
   大容量通信とゲーム通信が同一フローに混在する場合、途中で別アダプターへ移動させません。接続先・ポート・プロトコル等で別フローになっている場合に限り個別に選択できます。
3. **プロセス名だけで通信種別を断定しない**  
   Fortniteの通信には認証、マッチメイキング、ゲームプレイ、コンテンツ配信等が含まれます。まず実測ログで、数百MBの通信がどのPID・宛先・プロトコル・フローで発生するか確認します。
4. **Windowsの標準ルーティングの制約**  
   インターフェース別ルートやメトリックの変更は宛先単位の制御が中心です。同一宛先に対する個別フロー制御にはWindows Filtering Platform (WFP) 等の追加実装が必要です。
5. **アンチチート互換性**  
   Fortnite/Easy Anti-Cheat等と共存するため、プロセス注入やゲームファイル改変は行いません。WFPドライバーを導入する段階では、署名・管理者権限・互換性・アンチチート規約を確認します。

## 開発ロードマップ

### Phase 1 - ネットワーク監視
- [x] アダプター一覧・状態・リンク速度を取得
- [x] 1秒間隔のアダプター別送受信速度を表示
- [ ] Wi-FiとUSBテザリングEthernetをユーザーが明示的に割り当て
- [ ] TCP接続一覧（PID、ローカル/リモートIP・ポート、状態）を取得
- [ ] UDPエンドポイントを取得（UDPはOS APIだけではリモート接続先との対応が完全に得られない場合がある）
- [ ] プロセス/フロー別の通信量を記録
- [ ] CSVログ出力

### Phase 2 - Fortnite通信の分析
- Fortnite起動・マッチ開始・マッチ終了時刻をログに記録
- PID/フロー別の送受信量を比較
- 数百MBの通信が独立フローか、ゲーム通信と同一フローかを確認
- 観測結果に基づき振り分けルールを確定

### Phase 3 - 振り分けエンジン
- フロー分類と判定閾値
- Wi-Fi / Ethernetの可用性監視
- フロー単位の経路固定・フォールバック
- WFPを使った必要最小限のリダイレクト/ポリシー制御を検討・実装
- 失敗時に通信を壊さず制御を解除するフェイルセーフ

### Phase 4 - UI・運用
- 自動/監視のみ/手動モード
- 閾値・観測窓・アダプター設定
- 通信一覧・速度グラフ・切替履歴
- ログ出力・診断情報のエクスポート
- 起動時実行（任意）

## 初期値（仮）

| 設定 | 初期値 |
|---|---:|
| 速度測定間隔 | 1秒 |
| 新規フロー観測窓 | 3秒 |
| Wi-Fi判定閾値 | 10 Mbps |
| 経路固定 | フロー終了まで |
| フォールバック | 利用可能なアダプター |

閾値は仮値です。Fortniteの実測ログを取得して調整します。

## 開発環境

## セキュリティ・安全性

Fortniteアカウントの安全性を最優先し、当面は読み取り専用の監視機能に限定します。プロセス注入、メモリ操作、パケット改変、独自ドライバー/WFPフィルターによる通信制御は実装しません。Epic Gamesはサードパーティーソフトウェアの安全性を保証していないため、本アプリによるBAN回避・安全性を保証するものではありません。

詳細は [Fortnite利用時の安全方針](docs/FORTNITE-SAFETY.md) を参照してください。

- 初期設定は監視専用（通信経路を変更しない）
- 接続先や通信量ログには個人情報が含まれる可能性があるため、ログ共有前に確認
- 不明な通信を遮断しない
